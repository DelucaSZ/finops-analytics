## Defeito de acessibilidade efetivamente reproduzido

**B-ACC-01 — Critical / Opportunities / navegação por tabs.** Em execução Chromium en-US com axe-core WCAG A/AA no run [#43015884709](https://github.com/DelucaSZ/finops-analytics/actions/runs/43015884709), foi registrado `aria-valid-attr-value`: `<button id="_r_5_-tab-open" role="tab" aria-controls="_r_5_-panel-open">Open · 1</button>` aponta para painel inexistente. Isso é defeito real de relação ARIA da UI, não erro de fixture.

**Correção implementada:** `frontend/components/ui/tabs.tsx` recebeu opção `hasPanels` (padrão `true`) e somente referencia o `tabpanel` ativo quando ele existe; `frontend/app/opportunities/page.tsx` usa `hasPanels={false}` para seus controles de navegação, que não renderizam `TabsContent`. A alteração não interfere na seleção de status nem nos payloads de negócio. **Revalidação axe-core pós-correção: `passed`** no E2E [#43017040037](https://github.com/DelucaSZ/finops-analytics/actions/runs/43017040037), sem violações reportadas nos cenários amostrados.

Os dois cenários de filtro de Opportunities falharam no primeiro run por leitura síncrona de uma URL alterada via Next Router assíncrono; o runner agora aguarda `severity=high` antes de verificar. Revalidação: os dois cenários de troca de locale em Opportunities passaram no E2E [#43017040037](https://github.com/DelucaSZ/finops-analytics/actions/runs/43017040037). A correção de teste compara controles com IDs estáveis, excluindo falsos positivos de paginação montada assincronamente.
