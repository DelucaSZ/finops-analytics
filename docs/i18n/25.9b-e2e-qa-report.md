## Escopo implementado

- Inventário explícito de 33 rotas: 24 funcionais protegidas, 5 públicas, 4 técnicas/redirects.
- Chromium real contra Next.js de produção e proxy HTTPS local, `aven.locale` com `Secure`, dois contextos/idiomas isolados, autenticação apenas por interceptação `/auth/me`, nunca bypass em produção.
- Smoke por rota/idioma: documento autenticado, `html[lang]`, heading, Language Selector disponível, ausência de redirecionamento ao Login, console/pageerror, tokens de tradução inválidos; screenshots desktop em execução full.
- Cenários funcionais em Billing, Inventory, Flow, Opportunities, RDS e Settings Appearance: dados sintéticos consistentes com tipos TS, seleção de filtro, parâmetros da API, troca de locale, estado dos `select`, cookie, URL e refresh.
- Amostra visual tablet/mobile em cinco módulos, overflow horizontal, screenshots por viewport, operação do Language Selector via teclado e varredura axe-core WCAG A/AA em componentes representativos.
- Contratos de fixtures verificados estaticamente em `frontend/tests/i18n-authenticated-fixtures.test.mjs`; endpoints desconhecidos respondem HTTP 503 e são registrados, nunca simulam sucesso sem contrato.
- Impede mutações administrativas/financeiras: só POST de leitura de Billing e token de teste CSRF são atendidos; demais mutações HTTP 403 interceptadas.
- GitHub Actions: quick smoke em CI e workflow dedicado de E2E completo; artefatos JSON/screenshots.

## Execução reproduzível

Após `cd frontend && npm ci && npm run build` e instalar `playwright-core@1.57.0` como no CI, executar:

```bash
npm run smoke:i18n:browser
npm run smoke:i18n:authenticated
npm run test:i18n:authenticated
```

Requer Chromium/Chrome e OpenSSL; `CHROME_BIN` pode apontar para o binário do navegador. Não executar contra infraestrutura produtiva: a aplicação usa `NEXT_PUBLIC_API_URL` de build e interceptação da rede de navegador. `report.json` é salvo em `frontend/artifacts/i18n-authenticated/`, incluindo `commit`, casos, endpoints sem fixture, erros e timestamps.

## Resultados e honestidade metodológica

**Status neste commit documental: `not_run`.** A criação de testes e workflows não comprova execução. Após os jobs concluírem, registrar commit exato, URL dos runs, número real de `passed`, `failed`, `blocked` e `not_run`. Resultados só devem ser declarados quando observados. O CI atual de 25.9 (#174) cobre apenas Login/Appearance; os resultados futuros deste workflow devem ser analisados separadamente.

**Limitações atuais:** screenshots não são testes visuais pixel-perfect; inclui axe-core nos cinco cenários visuais (sujeito à execução do CI), mas não inclui leitor de tela nem auditoria automatizada de todas as rotas; nem todos os estados de formulários, erros, viewers/admin e fluxos de negócio foram modelados; vários endpoints de Settings usam apenas fallback de erro HTTP (report `unknownEndpoints`). Browser + backend simulado não valida permissões reais nem contratos end-to-end. A Fase 25 segue não homologada.
