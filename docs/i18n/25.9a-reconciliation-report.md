## Resumo

Foram preservados **2608 IDs históricos únicos** (Task 25.1). A reconciliação separa evidências de uso de chave do catálogo, valores técnicos, conteúdo externo, laboratório de desenvolvimento inacessível em produção, falhas demonstráveis em JSX e pontos que exigem verificação individual. Nenhum `needs_review` é automaticamente defeito.

A reconciliação foi fundamentada em código e catálogos do PR #174. O reconciliador `frontend/scripts/reconcile-i18n-baseline.mjs` usa AST TypeScript e as APIs dos validadores existentes; permite verificar referências, classificar novos candidatos e revalidar evidências documentadas. Correções de falsos positivos foram baseadas em inspeção de código, sem alterar algoritmos ou UI.

## Como reproduzir e auditar

1. `cd frontend && npm run audit:i18n:baseline` valida a integridade dos IDs, evidências e referências AST, paridade de valores registrada, deterministicidade e igualdade do CSV aprovado; também é executado no CI.
2. `npm run audit:i18n:baseline:write` regrava de forma determinística o snapshot **preservando classificações adjudicadas com evidência verificável**. `node scripts/reconcile-i18n-baseline.mjs --candidates` mostra classificações AST novas não adjudicadas; `--refresh` desconsidera classificações previamente revisadas e exige nova análise antes de substituir o CSV.
3. `npm run lint:i18n`, `npm run lint:i18n:references`, `npm run lint:i18n:coverage` (base correta do PR), `npm test`, `npm run typecheck` e `npm run build` permanecem validados pelo CI.
4. A base original `docs/i18n/25.1-translation-inventory.csv` não foi substituída. Os campos `current_file`, `current_line`, `translation_namespace`, `translation_key`, valores dos catálogos, método, evidência e pendência permitem replicar cada achado.

## Principais decisões de evidência

- **Uso contextual:** referências diretas AST, referências em componente renderizado e alguns vínculos indiretos demonstráveis em RDS e Settings. O vínculo em valor de catálogo isolado não é suficiente.
- **Técnicos:** códigos AWS/OCI/ARN/OCID, siglas SKU/HTTPS, viewBox/transformações SVG e expressões TypeScript não foram tratados como copy. Enums textuais como `FAILED` foram separados de rótulos localizados na apresentação.
- **Conteúdo externo:** apenas expressões dinâmicas rastreáveis foram classificadas como `external_content`; outras dependem de comprovação de contrato.
- **Obsoletos:** 149 registros do laboratório `/dev/ui` estão fora da experiência de produção por `notFound()` condicional; resposta do proxy em staging não foi verificada.
- **Lacunas:** 8 literais de apresentação comprovados na fonte, discriminados por arquivo e ID em `25.9a-actionable-gaps.md`; testes de navegador definirão impacto e severidade final.
- **Pendências:** 595 registros mantêm justificativa e ação individual sem criar defeitos artificiais.

## Riscos e aceitação

Permanece necessária auditoria semântica dos casos parametrizados/ICU, chaves dinâmicas e chamadas indiretas ainda não vinculadas. Não foi efetuada homologação da Fase 25 integral, nem alterações em APIs, auth, design tokens, consultas ou cálculo financeiro. A Frente B é obrigatória para validar rotas, acesso por perfis, estados e formatação em navegador com dados controlados.
