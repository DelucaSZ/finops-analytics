# Task 28.5 — Aven AWS Pricing Settings UI

## Escopo e arquitetura

A área administrativa `/settings/pricing/aws` consulta o catálogo regional AWS já persistido pelas Tasks 28.2–28.4. **Não** consulta a AWS Pricing API no navegador, não cria uma segunda tabela de preços, não permite editar tarifas oficiais e não muda Calculadora/Políticas AWS (28.6/28.7), Billing, coletores ou Pricing OCI.

Fluxo de leitura: Next.js com sessão/CSRF Aven → FastAPI `/api/v1/pricing/aws` (RBAC admin) → `AwsPricingProduct`, `AwsPricingRateDetail`, `PricingCatalogItem`, `AwsPricingSyncRun`, `AwsPricingSyncState`. A API usa `coverage_report` e `AwsPricingSynchronizer.status` da Task 28.4. Valores monetários são formatados como *strings* decimais de até oito casas, sem aritmética monetária em `Number`.

Fluxo de escrita: administrador com reautenticação recente e CSRF → `POST /sync` → `aws_pricing_sync_requests` (migration 0042) → worker `AwsPricingManualScheduler` / `AwsPricingManualQueue` → `AwsPricingSynchronizer.run_unit` → importador oficial da 28.3. O HTTP devolve `202` **sem executar download ou parsing**. O scheduler automático da Task 28.4 pode continuar desabilitado; o consumidor manual do worker é independente e somente processa solicitações quando `AVEN_AWS_PRICING_IMPORT_ENABLED=1`.

## Navegação e interface

- `Configurações → Preços AWS / AWS Pricing` — apenas administradores.
- `Configurações → Preços OCI / OCI Pricing` — inalterado.
- Região dinâmica de contas AWS ativas, regiões administrativas extras ou regiões já presentes no catálogo/estado. Preferência inicial por `sa-east-1` quando disponível.
- Serviço dinâmico do catálogo e serviços configurados; inicialmente, `AmazonEC2`, `AmazonRDS`, `AWSELB`, `AmazonVPC` (códigos da fonte; componentes como EBS e IPv4 podem compartilhar Service Code).
- Pesquisa server-side por SKU, Rate Code, descrição, família e atributos do produto; filtros por região, serviço, estado e data de referência (UTC); paginação de 25/50/100 registros.
- Tabela de tarifas: código de serviço, região, produto, SKU, descrição, unidade, preço, vigência e estado. IDs longos são truncados visualmente, mantendo o dado original e opção de copiar nos detalhes.
- Modal de tarifa: atributos, identidade da tarifa, origem, versão temporal, import batch e histórico paginado. Histórico filtrado por identidade financeira completa, inclusive região, SKU, rate code e unidade.
- Operação: last attempt ≠ published catalog ≠ freshness, última publicação válida, próxima execução, batch, cobertura por componentes mínimos, histórico paginado de execuções, detalhes e contadores.
- Interface com Design Tokens existentes, selects `NativeSelect`, layout full-width, scroll horizontal **somente dentro** das tabelas, temas Light/Dark/System e mensagens PT-BR/EN-US.

## Endpoints

Todos sob `/api/v1/pricing/aws`, autenticados e sujeitos a `require_admin`:

| Método | Endpoint | Uso |
|---|---|---|
| GET | `/meta` | Regiões, serviços, moeda e opt-in de importação |
| GET | `/products` | Produtos regionais, pesquisa e paginação |
| GET | `/rates` | Tarifas com vigência, status, busca e paginação |
| GET | `/rates/{id}` | Detalhes financeiros/técnicos |
| GET | `/rates/{id}/history` | Histórico temporal da mesma identidade regional |
| GET | `/sync/status` | Estado publicado, última tentativa e freshness separados |
| GET | `/sync/coverage` | Relatório de componentes mínimos por unidade |
| GET | `/sync/runs` | Histórico de execuções com paginação |
| GET | `/sync/runs/{id}` | Detalhes operacionais, erro, contadores |
| GET | `/sync/requests/{id}` | Acompanhamento de solicitação manual |
| POST | `/sync` | Enfileiramento unitário, exige `require_recent_admin` |

Parâmetros de listagem têm limites (em geral `limit ≤ 100`, `offset ≥ 0`, `q ≤ 160`). `region` exige código regional AWS válido. A publicação manual exige `service_code` configurado, região previamente conhecida, flag de importação ativa e confirmação explícita do operador no frontend. Conflitos de solicitação por serviço/região resultam em `409` estruturado; a migration aplica índice único parcial em estados `queued/running`, evitando corrida entre administradores. O importador e o sincronizador mantêm seus próprios advisory locks, cotas e regras de publicação.

## Precisão e integridade financeira

- `price` trafega como texto decimal, por exemplo `"0.00425000"`; apresentação com 8 casas, sem arredondar indiscriminadamente a `US$ 0,00`.
- Tarifa `0.00000000` é **preço zero válido**, distinto de SKU ausente ou região não sincronizada.
- Status `active` exige tarifa habilitada, status de pricing ativo e vigência `[effective_from, effective_until)` válida.
- Regiões são isoladas e não há fallback inter-regional.
- Importações malsucedidas não eliminam o último catálogo válido; estado de tentativa, status de catálogo e freshness são campos independentes.
- Cobertura `complete` atesta **somente o conjunto mínimo de componentes**, nunca 100% dos SKUs/configurações.

## Segurança e operações

`GET` exige sessão admin; `POST` exige admin reautenticado nos últimos cinco minutos, proteção CSRF já existente e opt-in `AVEN_AWS_PRICING_IMPORT_ENABLED=1`. Não há parâmetro de URL arbitrária, credencial no payload ou edição de preço importado. A fila registra o identificador do administrador, timestamps, status, modo, resultado e erro. O worker reprocessa solicitações `running` abandonadas há pelo menos 12 horas; execução simultânea permanece limitada pelos advisory locks do sincronizador. A solicitação `busy` retorna à fila sem publicar.

### Procedimento controlado

1. Aplicar a migration 0042 no startup normal do API (worker espera a versão do banco).
2. Garantir que o worker dedicado esteja operacional. Habilitar `AVEN_AWS_PRICING_IMPORT_ENABLED=1` **somente após autorizar o uso da fonte oficial**, em API e worker.
3. Em Settings → Pricing AWS selecionar região e Service Code; revisar cobertura/ausência de tarifas; iniciar uma validação sem publicação ou sincronização unitária.
4. Acompanhar `/sync/requests/{id}` e `/sync/runs` até a conclusão; conferir histórico, last-good, erro e cobertura. Não executar importação massiva de produção apenas para validar a UI.
5. Desabilitar a flag após a operação, quando desejado. Isso não apaga preços publicados.

## Testes e limites

Incluídos `backend/app/tests/test_aws_pricing_admin_api.py`, `backend/app/tests/test_aws_pricing_manual_queue.py` e `frontend/tests/aven-aws-pricing-settings.test.mjs`. Cobrem RBAC, entradas inválidas, isolamento entre regiões, string decimal, histórico, opt-in, deduplicação da fila e traduções/navegação. Fixtures são sintéticas e não comprovam preços públicos reais.

Validação esperada em CI: `ruff check .`, `ruff format --check .`, `pytest -q`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` e Docker build. A matriz visual exige ambiente de navegador autenticado com duas regiões e dados fixture em 1920/1440/1366/1280/1024/768/390/360 px, PT-BR/EN-US, Light/Dark/System. **Não considerar inspeção estática substituta da homologação visual de navegador.**

Limitações: somente On-Demand oficial suportado pelo importador atual; cobertura por componentes mínimos não garante SKU específico; a pesquisa de texto em atributos JSON pode ser onerosa para catálogos muito grandes e requer observação/otimização de índices em produção; fila manual depende de worker ativo e os registros podem permanecer `queued` enquanto ele estiver offline; não foi autorizada importação live nem implantação.
