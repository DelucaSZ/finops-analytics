# Task 27.4 — OCI VM & Base Database Service adapters

**Implementation branch:** `feat/task-27.4-oci-vm-db-system-calculator`  
**Scope:** backend only; simulation-only API; OCI BRL prices are final. CI/operational validation pending.

## Existing contracts reused

- `POST /api/v1/calculator/estimate` uses the same `CalculatorEstimateRequest`,
  `CalculatorMeteredComponent` and `estimate_calculator_cost` as AWS.
- Every monetary rate is resolved at one requested UTC instant using
  `CalculatorCatalogAdapter` → `PricingResolver` → `pricing_catalog_items`.
- Values, provenance, effective intervals, missing SKU statuses, decimal precision,
  quantity multiplication and temporal usage all come from existing contracts.
- OCI prices are commercial **BRL** and are never discounted, converted or taxed
  again. AWS-specific financial terms on an OCI request produce HTTP 422.
- No resources, user credentials, financial records or pricing catalog rows are modified.

## Compute VM

Supported exact priced shapes: `VM.Standard.E3.Flex`, `VM.Standard.E4.Flex`,
`VM.Standard.E5.Flex`, as selected by the existing OCI allowlist. Standard memory
configurations only: E3/E4 max 64 OCPUs, E5 max 94 OCPUs; memory must be at
least the OCPU count and at most 64 GB/OCPU, capped at 1024 GB.
Extended-memory or burstable instances are not currently offered.

Price components (all resolved from the persistent BRL catalog):

| Component | Catalog SKU | Unit |
| --- | --- | --- |
| OCPU | `VM.Standard.E3/E4/E5.Flex.OCPU` (exact family SKU) | `OCPU_HOUR` |
| RAM | `VM.Standard.E3/E4/E5.Flex.Memory` (exact family SKU) | `GB_RAM_HOUR` |
| Windows Server, when explicitly selected | `WINDOWS_LICENSE_OCPU` | `OCPU_HOUR` |
| Boot/Block Volume capacity | `BLOCK_VOLUME_GB_MONTH` | `GB_MONTH` |
| Boot/Block Volume performance, when VPU/GB > 0 | `BLOCK_VOLUME_VPU_GB_MONTH` | `VPU_GB_MONTH` |

CPU and memory: OCPU × rate × billable hours + RAM GB × rate × billable hours.
Windows Server licenses are separately charged per OCPU. Linux has no additional
Windows license component. Unknown OS yields a known subtotal but no final price.
OCI supports BYOL licensing for some Windows images, but that mode has **not**
been verified/modeled for this calculator; `windows` means OCI-provided license.

Boot Volume and each Block Volume are independent components: capacity GB ×
monthly rate plus GB × configured VPU/GB × performance monthly rate. A VPU tier
of zero is valid and incurs no VPU fee. Missing VPU tier does not mean zero.
Each additional volume has its own capacity, tier and count. Boot Volume count
must be one per VM. The old `boot_volume_gb` and `vpus_per_gb` fields are accepted
for migration; supplying old and new boot fields together returns HTTP 422.
A missing boot volume prevents a complete VM estimate.

Reference month uses 744 hours for hourly Compute and for linear monthly
capacity/performance proration. Compute VM per-second billing has a 60-second
minimum; Windows per-OCPU license is per second. Storage is prorated using
the declared 744-hour reference convention. The period engine handles hours,
days, weeks, fractional intervals, UTC timestamps and resource quantity.

**Catalog region warning:** the imported commercial catalog is not keyed
by region; `region` is retained for simulation context, but regional availability
and tenancy quotas are not certified. Actual deployment requires independent
service availability and contract verification.

### Example Compute VM request

```json
{
  "provider": "oci",
  "region": "sa-saopaulo-1",
  "resource_configuration": {
    "service": "compute", "shape": "VM.Standard.E4.Flex",
    "ocpus": 4, "memory_gb": 32, "operating_system": "linux",
    "boot_volume": {"size_gb": 100, "vpus_per_gb": 10},
    "block_volumes": [{"size_gb": 500, "vpus_per_gb": 10}]
  },
  "quantity": 2,
  "period": {"mode": "weeks", "amount": "3"}
}
```

With the **test-only fixture rates** matching the initial imported catalog
(not a live pricing quote), this produces BRL **712.24** per reference month
and BRL **482.48** for three weeks. All component prices and source/version
metadata in the live response are resolved from the deployed database.

## DB System: verified mapping before rate resolution

OCI Base Database Service has retired OCPU-metered service SKUs and older
VM.Standard.x86 provisioning options effective **July 31, 2026**.
New estimates are intentionally restricted to one-node
`VM.BaseDB.x86`, with ECPU values **4–256 in steps of 4**,
and Standard/Enterprise/Enterprise High Performance editions.
No automatic OCPU→ECPU conversion occurs. RAC, Exadata, developer edition,
unverified storage modalities and other DB products are not supported.

The existing `pricing_catalog_items` table only identifies `service`, `sku`,
`unit` and currency; it has no verified database edition/shape/licensing
attributes. To prevent associating the wrong price with a configuration,
migration `0039_oci_db_calculator_bindings` adds a **metadata-only** table:
`oci_db_calculator_bindings`. This is NOT a parallel pricing catalog.

Each binding documents a **region + deployment + shape + edition + licensing
model + CPU unit + component** and references the actual approved SKU/unit
stored in `pricing_catalog_items`, with a nonempty `source_reference`.
The table stores no rates; a separate verified binding must be entered for
each distinct configuration. No binding or fake DB SKU is seeded.
Existing OCI Settings price administration is untouched.

Supported binding components:

- `capacity`: database compute/capacity service rate in `ECPU_HOUR`.
- `license`: separate Oracle Database software license charge in `ECPU_HOUR`
  **only** for License Included when the capacity price does not bundle license.
- `storage`: database storage rate under service `db_system` in `GB_MONTH`.

The explicit `includes_license` flag on a capacity binding prevents
charging both bundled and separate license prices. BYOL must use a
distinct verified BYOL capacity price binding and requires eligible existing
Oracle license entitlements; BYOL does not receive a fictitious free
License Included charge. A binding is never inferred from an OCI Compute VM SKU.

**Current catalog status:** the initial nine OCI commercial rows contain no
DB System prices or mappings. These remain pending per supported shape/edition,
license mode and storage: ECPU capacity, License Included unbundled license
when applicable, BYOL-specific rate, and verified database storage.
Catalog entries and approved bindings can be added later without modifying
the calculator engine or historical migrations.

### Example DB request

```json
{
  "provider": "oci",
  "region": "sa-saopaulo-1",
  "resource_configuration": {
    "service": "db_system", "deployment_model": "base_database",
    "shape": "VM.BaseDB.x86", "edition": "enterprise",
    "license_model": "license_included", "cpu_unit": "ECPU",
    "cpu_count": 4, "storage_gb": 500
  },
  "period": {"mode": "days", "amount": "15"}
}
```

Without bindings, status is `sku_missing`, the missing entries are
`db_system_capacity_sku_mapping`, `db_system_license_sku_mapping` and
`db_system_storage_sku_mapping`. No final price is returned.
With capacity and storage priced but license absent, status becomes
`partially_priced`, with `monthly_known_subtotal` and
`period_known_subtotal` only; final totals are **null**.
When all required verified bindings resolve effective BRL rates,
`pricing_status` becomes `priced`. Separate ECPU and OCPU rates are never
interchanged.

## API and dropdown metadata

- Existing authenticated `POST /api/v1/calculator/estimate` dispatches
  `provider=oci`, `service=compute` or `service=db_system`.
- Authenticated `GET /api/v1/calculator/oci/options?service=compute&region=sa-saopaulo-1`
  returns allowlisted shapes, sizing bounds, VPU tiers and each family's catalog availability.
- Authenticated `GET /api/v1/calculator/oci/options?service=db_system&region=sa-saopaulo-1`
  returns only explicitly verified product-binding combinations and
  `complete_price_available`; it is empty with `setup_required=true` until
  product mappings are approved and inserted.

Both endpoints use the existing session/permission boundary and catalog read
access; they do not provision cloud resources or recalculate monetary values
in a UI. Task 27.5 must use the standardized Aven dropdown components and
the returned prices/statuses.

## Known exclusions and validation

Estimates exclude network egress, public IPs, load balancers, backups,
Object/File Storage, optional services and contract terms outside the catalog.
DB System multi-node/RAC and unusual premium storage modes remain unquoted.
An effective but incorrect-currency or ambiguous row remains a pricing error.
Missing SKUs never become zero, missing configurations remain incomplete,
and an invalid configuration is rejected before any definitive estimate.

Test coverage: `backend/app/tests/test_oci_calculator.py`,
`backend/app/tests/test_calculator_engine.py` and existing OCI pricing
regression modules. Production acceptance additionally requires a catalog
audit against approved Oracle commercial SKUs and live regional availability.
