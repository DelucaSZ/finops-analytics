# Task 27.2 — Aven Cloud Cost Calculator: financial and temporal engine

**Status:** implemented in branch `feat/task-27.2-calculator-engine`; PR/CI validation pending.  
**Dependency:** Task 27.1, including its post-merge response invariants (PRs #181 and #182).  
**Scope:** generic backend engine, authenticated read-only endpoint, tests and documentation.
No cloud service rate source, price import, resource provisioning or UI introduced here.

## Architecture

`POST /api/v1/calculator/estimate` → `CalculatorEstimateRequest` → future service-specific
adapter supplying `CalculatorMeteredComponent` → `estimate_calculator_cost` →
`CalculatorEstimateResponse`.

The engine accepts a list of required, already validated components, each with:

- A `CalculatorPriceLookup` resolved at a **single aware UTC reference instant** by
  the 27.1 `CalculatorCatalogAdapter`/`PricingResolver`;
- Stable component key, catalog identity, price/version/source/currency and status;
- `units_per_resource` (e.g. OCPUs, GB of RAM, provisioned GB, ECPUs);
- Explicit `reference_month_hours` for **that** component;
- For `*_HOUR`, `*_MINUTE` and `*_SECOND`: required `increment_seconds` and
  `minimum_billable_seconds` (default 0) from the provider-specific commercial rules;
- For `*_MONTH`: linear fractional-month proration with a per-component reference
  month; no second-based rounding;
- AWS contractual `discount_eligible`, never valid on OCI components.

`oci_compute_catalog_identities` and `OCI_MONTHLY_HOURS=744` remain available for
the future OCI VM adapter, with no duplicate OCI price tables or new migrations.
**AWS has no global 730/744-hour assumption**: each adapter must explicitly supply
the verified monthly reference for each component. There is no automatic conversion
between hours and calendar months across unrelated SKUs.

## Temporal model

Supported input periods: `monthly`, fractional `hours`, `days`, `weeks`, or
`custom` start/end timestamps (exclusive end), both timezone-aware. Custom
timestamps are normalized to UTC **before** subtraction to handle daylight-saving
transitions. Maximum permitted elapsed duration is five 366-day years. An
effective duration in hours is returned as `period_duration_hours` for nonmonthly
periods; reference-month mode has no single global duration.

For a per-hour component, with unit quantity `q`, resource count `n`, monthly
hours `H`, elapsed seconds `t`, second billing increment `i` and minimum
seconds `m`:

```text
monthly_units = q * n * H
billable_seconds = max(m, ceil(t / i) * i)
period_units = q * n * billable_seconds / 3600
```

Minutes/seconds use 60/1 as the denominator; monthly rate units use:

```text
monthly_units = q * n
period_units = q * n * t / (H * 3600)
```

`monthly` mode sets period units equal to monthly units. Monthly cost and
selected-period cost are independent outputs, not multiples of already rounded
monthly values. Pricing uses a **single catalog snapshot** at
`pricing_reference_date` (or one sampled UTC `now`) and applies that snapshot to
the entire simulated duration, documented by
`price_snapshot_applied_to_entire_period`; the engine does not split at future
effective price boundaries. The adapters must validate service-specific usage
minimums, regional eligibility, capacity, licensing and unsupported combinations
before supplying components.

## Financial policy

All multiplication and financial adjustment use Python `Decimal`, with
`ROUND_HALF_UP` to 2 decimals at the **reported aggregate** and line-item
presentation boundaries, not between calculations. The global cost guard is
`1e18` per intermediate result. `units_per_resource` and the explicit monthly
hours must be finite, positive and within guard limits; billing increments and
minimums must be nonnegative and bounded. Percentage inputs are bounded:
discount 0–100%, tax 0–1000%, manual FX >0 and ≤1,000,000.

AWS original USD cost is the sum of eligible and non-eligible raw components.
The 27.1 primitive applies only the eligible discount, then optional USD/BRL
conversion, then configurable tax (13% default, only with conversion enabled).
Both monthly and selected-period discounts, FX and taxes are returned separately.
The 27.1 `discount_amount` and `tax_amount` singular fields retain **monthly**
meaning; new `monthly_*` and `period_*` fields remove ambiguity.

OCI uses raw catalog **BRL as final**: original = net = final for both periods.
OCI never accepts AWS financial terms and cannot declare discount eligibility.

## Pricing completeness

All required priced components yield `pricing_status=priced`; verified zero-price
catalog rows are allowed. If required prices are missing, no definitive total is
returned. `partially_priced` exposes `monthly_known_subtotal` and
`period_known_subtotal` only, **never** as total. When all are missing, the
aggregate uses a precise failure code (`sku_missing`, `price_not_effective`,
`pricing_configuration_error`, etc.). Each component retains provenance, usage,
rounding, billing basis and individual status.

In Task 27.2 the HTTP boundary **does not yet register any EC2/RDS/OCI
production adapter**, as those require the explicit SKU and eligibility work in
Tasks 27.3–27.6. Therefore it currently responds with HTTP 200,
`pricing_status=unsupported_configuration`, null final totals and
`service_adapter_not_available` for valid requests. This is intentional and is
not a live resource quotation or mock production catalog.

## API contract

`POST /api/v1/calculator/estimate` requires an existing browser session, CSRF
header and existing permissions, through `require_user`. The endpoint is
simulation-only and marked `Cache-Control: no-store`.

Example request (valid input, currently unavailable until EC2 adapter is linked):

```json
{
  "provider": "aws",
  "region": "sa-east-1",
  "resource_configuration": {"service": "ec2", "instance_type": "t3.medium"},
  "quantity": 2,
  "period": {"mode": "weeks", "amount": "3"},
  "pricing_reference_date": "2026-11-11T00:00:00Z",
  "aws_financial": {
    "discount_percent": "10",
    "conversion_enabled": true,
    "usd_brl_rate": "5.00",
    "tax_percent": "13"
  }
}
```

Current reply includes `pricing_status: "unsupported_configuration"`,
`monthly_final_cost: null`, `period_final_cost: null`, `final_currency: "BRL"`,
`pricing_currency: "USD"` and
`warnings: ["price_snapshot_applied_to_entire_period", "service_adapter_not_available"]`.

Numerical example verified by unit test using **test-only** components: a one-hour
USD 1.00 eligible compute component and USD 0.20 ineligible component, on a
720-hour declared reference month; 10% discount, manual USD/BRL=5.00 and 13% tax
produce reference-month USD 864 original, USD 792 net and BRL 4,474.80 final;
one-week period USD 201.60 original, USD 184.80 net and BRL 1,044.12 final.
These rates are illustrative test fixtures, **not** a live AWS pricing catalog.
