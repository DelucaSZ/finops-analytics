# Task 27.3 — AWS EC2 & RDS calculator adapters

**Implementation branch:** `feat/task-27.3-aws-ec2-rds-calculator`  
**Scope:** authenticated read-only AWS estimates in the existing Task 27.2 engine; no UI and no OCI changes.

## Architecture and provenance

`POST /api/v1/calculator/estimate` dispatches AWS requests through
`aws_calculator.estimate_aws_calculator`. The adapters only resolve products
and describe how each charge is metered. `calculator_engine` remains the single
source of truth for quantity scaling, temporal metering, rounding, eligible
discount, user-supplied USD/BRL rate, and tax.

`aws_calculator_pricing.AwsPublicPriceResolver` calls the official
**AWS Price List Query API** (`pricing:GetProducts`) with `boto3`.
It queries the **us-east-1 Pricing API endpoint**, while the requested
`regionCode` is an explicit product selector and is rechecked on each
result. The Pricing API endpoint region is not the simulated EC2/RDS region.

The resolver checks product family, SKU attributes, On-Demand term, currency
USD, rate dimension, untiered usage bounds and effective date. It rejects
unavailable, ambiguous and mixed configuration prices instead of returning a
zero or choosing a different region. Returned component SKUs contain the
AWS product and rate codes, unit price, reference time, effective date,
`source=AWS_PUBLIC_PRICE_LIST`, plus billing precision. It uses bounded
lookups, network timeouts, a maximum 12-page query and a one-hour bounded
in-memory cache; errors are explicit, not substituted with historic billing.

**The public AWS Price List API is not a historical price archive.**
An explicit historic `pricing_reference_date` is checked against the
current available term effective date, but the calculator cannot reconstruct
all previous AWS rate versions. The warning
`aws_price_list_current_snapshot_not_historical` is always returned. This
is a scenario estimate, not a prediction of future AWS catalog or tax changes.

## Runtime AWS permissions

The backend's own AWS credential chain (for example, its EC2 instance profile)
must be granted only:

```json
{
  "Effect": "Allow",
  "Action": ["pricing:GetProducts", "pricing:GetAttributeValues"],
  "Resource": "*"
}
```

The estimator has no AWS cloud-account selector and does **not** assume roles
into integrated customer accounts. If the backend has no suitable AWS credentials,
cannot reach the Pricing API, or has insufficient rights, the quote has null
final totals and an explicit pricing error. No changes to customer onboarding
CloudFormation templates are necessary; deploy permission on the central backend
role. SDK calls are read-only and do not create infrastructure, pricing rows,
Billing entries or reservations.

## Supported EC2 contract

```json
{
  "provider": "aws",
  "region": "sa-east-1",
  "resource_configuration": {
    "service": "ec2",
    "instance_type": "t3.medium",
    "operating_system": "linux",
    "purchase_option": "on_demand",
    "tenancy": "shared",
    "root_volume_gb": "100",
    "ebs_volume_type": "gp3",
    "ebs_volume_count": 1,
    "ebs_iops": 3000,
    "ebs_throughput_mbps": 125
  },
  "quantity": 2,
  "period": {"mode": "weeks", "amount": "3"},
  "aws_financial": {
    "discount_percent": "10",
    "conversion_enabled": true,
    "usd_brl_rate": "5",
    "tax_percent": "13"
  }
}
```

The EC2 adapter matches the public shared-tenancy On-Demand Compute Instance
SKU for the requested region, exact instance type and OS (Linux/Windows).
It allows gp2/gp3 EBS capacity, volume count and gp3 provisioned IOPS/throughput
above the included baseline (3,000 IOPS and 125 MiB/s). Extras must resolve
their own monthly-priced product or the entire estimate remains incomplete.
Windows pricing includes the OS in the EC2 SKU and is **never** billed as
another license line. Dedicated, Spot, Savings Plans, Reserved Instances, RHEL,
SUSE and marketplace images are excluded.

EC2 reference monthly instance usage is **730 hours** per selected instance;
EC2 instance usage is billed per second, minimum 60 seconds. EBS monthly
dimensions are prorated under an explicit **720-hour (30-day) reference month**,
per-second with 60-second minimum. These are distinct monthly comparison
conventions, not a universal month or actual calendar charge promise.

## Supported RDS contract

```json
{
  "provider": "aws",
  "region": "sa-east-1",
  "resource_configuration": {
    "service": "rds",
    "engine": "postgres",
    "instance_class": "db.t3.medium",
    "deployment": "single_az",
    "storage_type": "gp3",
    "allocated_storage_gb": "100"
  },
  "quantity": 1,
  "period": {"mode": "days", "amount": "15"},
  "aws_financial": {"discount_percent": "5"}
}
```

Current implementation targets traditional **RDS PostgreSQL, MySQL and
MariaDB DB instances**, either Single-AZ or *traditional* Multi-AZ, only if the
corresponding live public Price List product exists in the selected region.
Multi-AZ instance and storage rates must each resolve to their matching AWS
SKU; the adapter does not assume a doubling multiplier. Supported storage
options are gp2 and gp3 with standard included performance. Additional
provisioned RDS IOPS/throughput, io1/io2, SQL Server and Oracle license editions,
BYOL, Aurora, serverless, RDS Custom and Multi-AZ DB clusters are **not yet
supported** and cannot receive a definitive price.

RDS instances are metered per second with **600-second minimum**. Provisioned
RDS storage is represented as an actual GB-month SKU, prorated under a declared
30-day/720-hour comparison month with a 600-second minimum for a newly billable
storage configuration.

If EBS or RDS storage is omitted entirely, the estimate covers only its
instance component and carries an explicit `*_storage_not_configured` warning.
It must not be interpreted as total infrastructure spend.

## Discounts and currency

The existing Task 27.2 financial engine applies user-entered
`discount_percent` (default 0%) to **eligible** components before any
currency conversion. It then multiplies net USD by the **manually** supplied
`usd_brl_rate` (optional conversion, default disabled), adds tax (default
13% when converting) and returns monthly and selected-period totals separately.

In the absence of a verified contract breakdown, the adapter conservatively
marks **Linux EC2 compute and open-source RDS compute** discount-eligible for
what-if simulation. It does **not** mark EBS/RDS storage or the inseparable
Windows-license-inclusive EC2 SKU discount-eligible. The entered percentage
is a scenario assumption, not evidence of real organization contract coverage.
Users must confirm actual eligibility before using a quote commercially.

Using deterministic **test-only** prices rather than actual AWS rates:
EC2 Linux USD 1.00/hour, two instances, each with 100 GB EBS gp3 at
USD 0.10/GB-month, 10% eligible compute discount, FX 5.00 and 13% tax produces
**monthly USD 1,480.00 original, USD 146.00 discount and BRL 7,537.10 final**.
The 3-week estimate is **USD 1,022.00 original**, USD 100.80 discount and
**BRL 5,204.78 final**. No claim is made that these are prices for any real SKU.

A test RDS PostgreSQL instance at USD 2.00/hour with 100 GB gp3 at
USD 0.20/GB-month, 5% eligible compute discount and a 15-day period yields
USD 1,480.00 original/month, USD 730.00 original/period and
**USD 694.00 final/period**.

## API endpoints for Task 27.5/27.7 UI

- `POST /api/v1/calculator/estimate` — existing authenticated estimator.
- `GET /api/v1/calculator/aws/regions` — current region codes from
  `pricing:GetAttributeValues`.
- `GET /api/v1/calculator/aws/options?service=ec2&region=sa-east-1&search=t3`
  — bounded/offset-paginated instance type and Linux/Windows combinations
  actually advertised as On-Demand in the selected region.
- `GET /api/v1/calculator/aws/options?service=rds&region=sa-east-1&engine=postgres&search=db.t3`
  — compatible class/deployment combinations. Engine keys currently exposed:
  `postgres`, `mysql`, `mariadb`.

All routes require the existing authenticated session and carry
`Cache-Control: no-store`. The metadata endpoints explicitly signal
AWS Pricing unavailability; they do not pretend that synthetic static
type lists are available in each region. Search requires at least two
characters and lists are bounded. They are not a substitute for full
runtime validity checks when submitting a quote.

## Known limitations and excluded components

No automatic account-specific rate, contract price, AWS credits, Savings
Plans/RI, data transfer, public IPv4/Elastic IP, snapshots, load balancers,
backup excess, CloudWatch, instance CPU credits or optional paid RDS I/O
requests are included. Such fees are not zero; they are out of scope.
Multi-AZ cluster prices, optional performance constraints beyond baseline,
past price reconstruction and regional service capacity are not guaranteed.

A missing mandatory SKU returns `sku_missing`, a mismatched/ambiguous or
unreachable price returns a non-priced status, and mixed successful/missing
components return `partially_priced` with a *known subtotal* only.
Neither status supplies a definitive monthly or period total.

## Testing and dependencies

`backend/app/tests/test_aws_calculator.py` exercises deterministic,
isolated Price List fixtures for EC2, RDS, Multi-AZ, EBS gp3 extra performance,
region correctness, Windows licensing, FX/discount/tax, custom periods,
minimum charges, omitted SKUs, duplicate products and Pricing API failure.
No production credentials or network are required for the test suite.

Operational acceptance additionally requires running a **live** pricing
connectivity check on the backend with its configured IAM role, testing actual
regional products and confirming discount coverage with the AWS contract.
This cannot be proven by repository-only deterministic tests.

Next step: Task 27.4 can focus on OCI price adapters or extend AWS commercial
coverage under an explicitly approved follow-up scope. The planned full Aven
visual calculator must consume the backend's priced components and status,
not recalculate amounts in the browser.
